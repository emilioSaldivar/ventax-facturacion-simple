## Protocolo del agente implementador

Resumen del PLAN §12; el PLAN manda si difieren.

1. Antes de cada tarea: leer `AGENTS.md`, `docs/PAUTAS_FRONTEND_v0.1.md` y esta cadena; `git status` y `git log -5`; releer las lineas del PLAN §10.0 (`git log -3 -- apps/web-operacion/src`).
2. Nunca agregar al commit ni modificar los archivos de la otra sesion: `TMP/`, `scripts/guia-uso-segel.cjs`, `docs/SPEC_IDENTIDAD_MARCA_SEGEL_v0.1.md`, `docs/PLAN_IDENTIDAD_MARCA_SEGEL_v0.1.md` mientras figuren sin commit. `git add` por archivo, nunca `-A`.
3. Un commit por tarea (`tipo(ux-resto): resumen (URA-0NN)`), en `feat/identidad-segel`. Nunca `master`, nunca PR, nunca despliegue a produccion ni a `segel-fs` sin confirmacion directa del usuario.
4. Validar con el stack local (`.local/segel-ensayo`) reconstruyendo API y frontend del mismo commit (PLAN §12.3). La clave del operador va en `ENSAYO_PASSWORD_FILE`, fuera del repo; no se copia a ningun archivo.
5. Si una validacion falla y no se corrige en el momento: anotar comando y salida en Evidencia, marcar `BLOQUEADA` y detenerse.
6. Lo que a nivel de experiencia parezca mejorable pero exceda la tarea: anotarlo en "Para revisar con el usuario", no resolverlo por cuenta propia.
7. Al cerrar: evidencia, lista de las pautas §12, linea base del reconocimiento actualizada si bajo, y SPEC/PLAN corregidos si difieren de lo hecho.
