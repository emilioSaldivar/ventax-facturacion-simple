## Descripcion del modulo

Cierre de tres brechas reportadas por el founder sobre el modulo de Recibos de Dinero (v0.1): (1) el PDF muestra `AUTH_REQUIRED` en vez del documento tanto al previsualizar como al descargar, (2) no existe forma de compartir un recibo por WhatsApp como si existe para notas y facturas, (3) el formulario y las acciones de recibo no siguen el sistema de estilos del resto de la app. Root cause de cada punto documentada en `SPEC_RECIBO_DINERO_v0.2.md`.

## Notas de producto

- No se modifica el modelo de datos ni las reglas de negocio de `SPEC_RECIBO_DINERO_v0.1.md`; esta iteracion es de corrección de bug + paridad de UX con Notas/Facturas.
- El endpoint publico nuevo (`/verificar/recibo/:token/pdf`) no expone mas datos que los que ya devuelve `GET /verificar/recibo/:token`; ambos ocultan datos si el recibo no esta `EMITIDO`.
- `buildWhatsAppShareUrl` y `normalizeParaguayWhatsAppDigits` no se tocan — se reutilizan desde el modulo de Notas.
- Si durante RD2-010 se determina que ninguna clase existente cubre bien el layout de un grupo de botones puntual, se documenta la decision aqui antes de introducir una clase nueva (no crear CSS nuevo sin necesidad).
